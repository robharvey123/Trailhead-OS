## P0 — the app does not currently render

Every route returns HTTP 500 in dev. Verified twice (Assessment B, then independently in the parent).

```
./app/globals.css
Parsing CSS source code failed
@import rules must precede all rules aside from @charset and @layer statements
```

`app/globals.css:1-2` is `@import 'tailwindcss';` followed by the Google Fonts `@import`. Turbopack expands the Tailwind import inline, which pushes the Google Fonts `@import` past thousands of generated rules and violates the CSS spec ordering rule. Stack is Next 16.1.4 + Tailwind v4 + Turbopack.

Fix: delete the Google Fonts `@import` at `app/globals.css:2` and load Inter + JetBrains Mono via `next/font` instead. This also resolves detector finding #1 and audit P2-2.

## Design Specificity Verdict

**Partially grounded, structurally interchangeable, internally at war with itself.**

The vocabulary is genuinely Rob's: Engagements / Timesheet / Quotes / Enquiries / Outreach, GBP + VAT + `en-GB` throughout, FreeAgent push, retainer hours-vs-cap bars. `HoursBar` (`components/os/PortfolioOverview.tsx:23-48`) is the single most product-specific thing in the codebase — colour escalates accent → amber at 80% → rose when over, and the label flips from a neutral `74%` to an accusatory `+3.2h over`. No generic dashboard component knows what an over-serviced retainer means.

The composition is a stock admin template: fixed 288px rail, unstyled content well, no top chrome. `components/os/OsShell.tsx:63-74` renders a `<main>` and nothing else — no topbar, no breadcrumb, no global search, no command surface. Each page then re-invents its header three different ways.

**Deterministic scan:** 22 findings, exit code 2 — 11 `overused-font`, 6 `side-tab`, 4 `gray-on-color`, 1 `bounce-easing`. On verification the detector is roughly half wrong, and wrong in an instructive direction. All 4 `gray-on-color` hits are false positives (mispaired classes across ternary branches; the real pairs measure 6.92:1, 4.84:1, 4.51:1 — all pass AA). 4 of 6 `side-tab` hits are legitimate blockquote and unread-email rails. `bounce-easing` is a chat typing indicator.

But the detector's one true hit was bigger than it knew: `overused-font` at `globals.css:2` is not a taste problem, it is the line breaking the build.

**What the detector missed entirely** — the real contrast failures, all found by reading tokens:
- `--text-3: #94A3B8` = **2.56:1** on white. Used **600 times across 116 files**. Every field label, timestamp, table sub-line, placeholder and sidebar group header in the OS.
- `.btn-primary` white on `#0EA5E9` = **2.77:1**. **57 uses across 39 files**.
- `.folder.active` / `.seg-toggle .active` = 2.42:1; `.tab.active` = 2.65:1 — the two "you are here" signals are the least readable elements on screen.

**Visual overlays:** not available. Browser injection was impossible because the app 500s. No overlay is rendered in any tab.

## Overall Impression

Two things are true at once, and the gap between them is the whole story.

The engineering judgment is better than the scores suggest. Zero fabricated metrics after a deliberate hunt — every stat, bar and percentage traces to a real query, and `PortfolioOverview.tsx:44` floors the *bar width* at 2% while leaving the displayed number truthful. Zero TODO/FIXME. Zero dead UI. Zero `'use client'` on all 67 OS pages. That restraint is rare and it is the hardest thing here to retrofit.

The distribution of good patterns is the failure. Almost every serious finding is a correct solution that already exists in this repo and was never propagated:

| Problem | Solution already in the repo |
|---|---|
| 66 keyboard-inoperable rows | `.row-link` stretched-`<a>`, `globals.css:668-673` |
| 28 overlays with no focus trap | native `<dialog>.showModal()`, `components/ui/ConfirmDialog.tsx:27` |
| Contrast failures | `--accent-strong` / `--green-strong`, `globals.css:426,436` |
| 22 overflowing tables | `overflowX` wrapper, `ContactsClient.tsx:109` |
| 515 unlabelled controls | nested `<label>`, `AccountForm.tsx:118` |
| 7-await waterfall | `Promise.all` — used correctly 82 times elsewhere |
| No code-splitting | `await import('exceljs')`, `ImportClient.tsx:160` |

This is a distribution problem, not a knowledge problem. Remediation is far cheaper than 8/20 and 15/40 imply.

**The single biggest opportunity:** the OS has no shell. Adding a topbar with breadcrumb + ⌘K search would fix heuristics 3, 6 and 7 at once, give the three competing page-header treatments one place to converge, and turn a generic admin template into a single operator's cockpit.

## Priority Issues

### [P0] The app does not render
Covered above. Everything below is unreachable until `globals.css:2` is fixed.

### [P0] Every toast in the app is silently discarded
`sonner` is a dependency, `toast.success`/`toast.error` is called in ~25 client components, and `grep -rn "Toaster" app components lib` returns **zero**. None of the five layouts mount it.
**Why it matters:** the entire success/failure channel for the money surfaces is dead. "Sent to FreeAgent as a draft invoice" (`InvoiceDetailClient.tsx:47`), "Payment link copied" (`:116`), "Recurring payment set up in Stripe" (`:176`) — all produce nothing. Rob cannot distinguish "worked" from "no-op" on Stripe and FreeAgent actions.
**Fix:** render `<Toaster position="bottom-right" richColors closeButton />` in `app/layout.tsx`, then route the inline `error` states (`DealsClient.tsx:234`, `Board.tsx:103`) through `toast.error` so there is one failure channel.
**Suggested command:** `/impeccable harden`

### [P0] Deleting a deal is unconfirmed and irreversible
`components/os/DealForm.tsx:220-226` calls `onDelete(deal.id)` straight from the click; `DealsClient.tsx:133-144` optimistically drops the row. No dialog, no toast, no undo — while `ConfirmDialog` sits unused two imports away and *does* guard the recoverable invoice delete.
**Riley's variant:** double-click it. No in-flight guard, so two DELETEs fire; the second 404s and `setDeals(previous)` at `:141` **restores the already-deleted deal to the UI**. The board now shows a deal that no longer exists in the database.
**Fix:** `ConfirmDialog` with `variant="destructive"`, description naming `formatCurrency(deal.value_amount)`, and `confirmPhrase={deal.name}`. Then a `toast.success` carrying an Undo that re-POSTs.
**Suggested command:** `/impeccable harden`

### [P1] Core interactions are keyboard-inoperable
66 non-semantic elements carry `onClick`. `role="button"` → **0**. `tabIndex` → 3, none on a clickable div. 28 of 28 `fixed inset-0` overlays lack a focus trap; 6 have an Escape handler; the dominant pattern is a bare `div` backdrop with `onClick={onClose}`, which is not keyboard-activatable — a literal keyboard trap.
All four kanban boards register `PointerSensor` alone with no `KeyboardSensor` (`Board.tsx:49`, `WorkstreamBoardClient.tsx:112`, `ProjectTaskPanel.tsx:251`, `ProjectWorkspaceClient.tsx:608`), so cards cannot be moved by keyboard at all.
`aria-live` → 0. `role="alert"` → 0. `aria-invalid` → 0. `aria-sort` → 0. `<th scope>` → 0.
**Fix:** adopt `.row-link` (`globals.css:668-673`) for rows; extract one `<Modal>` from the native-`<dialog>` implementation at `components/ui/ConfirmDialog.tsx:27`; add dnd-kit's `KeyboardSensor` + `sortableKeyboardCoordinates`.
**Suggested command:** `/impeccable harden`

### [P1] Two contrast tokens fail AA across ~657 call sites
`--text-3: #94A3B8` at 2.56:1 (600 uses) and `.btn-primary` at 2.77:1 (57 uses), plus the active-tab and active-folder states at 2.42–2.65:1. `--accent-strong: #0369A1` already exists at `globals.css:426`, labelled "readable accent text on light bg", and measures 5.17:1.
**Fix:** darken `--text-3` to ~`#64748B` (4.6:1) and swap the active-state selectors to the `-strong` variants. Two token edits fix ~657 sites.
**Suggested command:** `/impeccable colorize`

### [P1] No global search, no command palette, and the dashboard throws away task identity
`components/nav/GlobalSearch.tsx` is imported by no file and hard-returns `null` unless the path matches `/workspace/:id` — a route that no longer exists. `OsShell` has no topbar for it to live in. And `getTaskHref()` at `DailyBriefClient.tsx:64-66` returns the constant `'/tasks'`, so every "Action required" row navigates to an unfiltered list.
**Why it matters:** the dashboard opens with "2 urgent actions" and then cannot take you to either one. The peak is followed within one interaction by the app forgetting what the user just told it.
**Fix:** 48px topbar in `OsShell` with breadcrumb + ⌘K trigger; rewrite `GlobalSearch` against a workspace-free `/api/search`; `getTaskHref(id)` → `/my-work/${id}?from=/dashboard`.
**Suggested command:** `/impeccable layout`

### [P1] Five visual systems in one app
`.thmock` light indigo (`globals.css:412-465`) · `(app)` slate-950 branded **"Brand Opps"** (`app/(app)/layout.tsx:20-21`) · `:root` lime/near-black · discovery terracotta · login slate-950. Clicking "Analytics" in the OS sidebar (`Sidebar.tsx:205`) walks straight from one into another.
Underneath: 11 distinct radii against 2 declared tokens, 3 conflicting font declarations, 2,765 raw Tailwind palette utilities across 113 files bypassing a 90-token layer that 155 files *do* use, and `--color-os-*` tokens referenced **0 times**.

**Suggested command:** `/impeccable polish`

### [P2] Responsive was not considered

**Suggested command:** `/impeccable adapt`

### [P2] "Email invoice" does not mark the invoice sent
`RecordEmailDialog` exposes an `onSent` callback (`:15,90`); `InvoiceDetailClient.tsx:248-257` mounts it without one. Rob emails a client, status stays `draft`, and a separate "Mark as sent" button (`:482-489`) is the only thing that moves it. Silent divergence between reality and record, on money.
Alongside: **one** `error.tsx` across 67 pages, no `not-found.tsx` anywhere, and `app/(os)/layout.tsx:31-65` swallows six query failures into bare `catch {}` blocks that zero the badge counts — so a broken Gmail token makes the Inbox badge read `0`, indistinguishable from a clear inbox.
**Suggested command:** `/impeccable harden`

### [P2] Seven-deep serial waterfall in the OS root layout

Also: only 7 of 67 pages have `loading.tsx` against CLAUDE.md's stated convention; `next/dynamic` → 0 uses, so TipTap ships in the initial inbox bundle and FullCalendar loads before the calendar is visible.

## Emotional Journey

**Entry is the high point and it is well judged.** `DailyBriefClient.tsx:186-198` composes "2 urgent actions · 7 tasks today · 1 quote needs attention" under a long-form date, and the empty states are dignified rather than cheerful: *"Nothing urgent today. The immediate queue is clear."*

**The first click off it is a betrayal.** The urgent task links to a generic `/tasks`, which loads a differently-titled page with three tabs and five filters and no highlight on the task just clicked.

**High-stakes moments are defended inconsistently.** Deleting a deal: no dialog, no toast, no undo. Sending an invoice: no confirmation, and the status silently stays draft. FreeAgent push: the button un-greys and nothing happens. Deleting an *invoice*: guarded properly, with reassuring honest copy ("This can be restored from the database if needed").

**There is no "done" moment anywhere.** Completing a task just makes a row disappear. Peak-end reads as: a calm, thoughtful morning greeting, followed by silence. The app never talks back.

## Questions to Consider

1. **If Rob is the only user, why does the OS behave like it has never met him?** No shortcuts, no recents, no pinned views, no saved filters, no "where I was yesterday." A single-operator OS is the one case where you can assume expertise from the first frame — and this one is built to the defaults of a product for strangers.

2. **The five workstreams were the product's spine — why are they gone from the navigation?** `CLAUDE.md:56-68` fixes them as the organising structure and `WorkstreamBadge` still exists, but the sidebar is now 21 modules grouped by *software category* (Delivery / Clients / Commercial / Insights). Is the nav modelling Rob's business, or the developer's file tree?

3. **A dashboard that opens with "2 urgent actions" and cannot take you to either — what is it for?** Should the Daily Brief be a page at all, or should it be the shell, with everything else opening beside it?

4. **Twenty-five call sites trust a toast layer that was never mounted. What else here is confidently talking to no one?** The `catch {}` blocks, the unused `/api/saved-views`, the orphaned `GlobalSearch`, the dead `dark:` swap, the second `ConfirmDialog`, `--color-os-*`. What is the cheapest check that catches all six at once?

5. **`ConfirmDialog` proves this codebase can build an excellent primitive — so why does it guard a recoverable invoice delete and not an irreversible deal delete?** Protection is distributed by when the code was written, not by what is at stake.
